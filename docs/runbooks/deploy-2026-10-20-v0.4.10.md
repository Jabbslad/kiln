## Installer and kiln-identity

The published bootstrap was downloaded and `sha256sum -c` was run before any host install. Its sha256 is `4cc7d0e3c5b1c77dd301de29e0d36288a396217714fcc882727804c63040a7ea`. `version=0.4.10`. It pins server archive `kiln-server-v0.4.10-x86_64-unknown-linux-gnu.tar.gz` at `f8ebc05462c03ca42612872f8c9d39ed0ef1003a00d19572b64fca82cb483673`. The only `identity` string in the bootstrap is the archive member `docs/identity-service.md`. On a host that already has `/etc/kiln`, `/opt/kiln`, or `/var/lib/kiln`, it runs `retire_public_door` and then that archive's `install.sh --apply`. `retire_public_door` edits `Sockets=` only when the line still names `kiln-door-proxy-public.socket`, runs `systemctl disable --now` on that socket when the unit is loaded, and restarts `kiln-door-proxy.service` only when one of those actions changed an active socket. It does not name `kiln-identity`.

The inner `install.sh` was extracted from the release archive and read before the host install. Its sha256 is `745fb0b3972ba6ff80923371a1e9b41d1cb322d9b954ca0b02cf6debcdf7cedf`, the same as `v0.4.10:deploy/install.sh`.
