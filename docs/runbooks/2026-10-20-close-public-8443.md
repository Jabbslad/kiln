## Why the service file had to change

`systemctl cat` before the close showed which unit owns which listener.

- `kiln-door-proxy-public.socket` has `ListenStream=78.46.98.73:8443` and `Service=kiln-door-proxy.service`.
- `kiln-door-proxy.socket` has `ListenStream=172.18.0.1:8444`.
- `kiln-door-proxy.service` had `Sockets=kiln-door-proxy.socket kiln-door-proxy-public.socket`. `systemctl show` reported `Wants=` including both sockets.

`systemctl disable --now kiln-door-proxy-public.socket` disabled the unit and closed systemd's fd. The proxy process, pid `47723`, kept the inherited fd, so `78.46.98.73:8443` was still listening and the service stayed active. `172.18.0.1:8444` stayed up. The bridge path was not killed by stopping the public socket.

`systemctl restart kiln-door-proxy.service`, which is the next line of the previous close procedure, started the disabled public socket again. After that restart the socket was `enabled=disabled` and `active=active`, and `ss` showed `78.46.98.73:8443` owned by the new proxy and by systemd. `https://cli.dark-forge.dev/` was still HTTP 401 via Caddy.

A drop-in at `/etc/systemd/system/kiln-door-proxy.service.d/no-public-socket.conf` set an empty `Sockets=` and then `Sockets=kiln-door-proxy.socket`. After `daemon-reload`, stopping the public socket, and restarting the service, `78.46.98.73:8443` was listening again and the public socket was active. That attempt was rolled back: the drop-in was removed, the public socket was enabled and started, and the proxy was restarted. `https://cli.dark-forge.dev/` returned 401 and the sign-in page returned 200. The public listener was back.

The second attempt edited the service unit itself, ran `daemon-reload`, and checked `Wants=` before stopping anything. `Wants=` no longer listed `kiln-door-proxy-public.socket`. `disable --now` then left the old proxy holding the 8443 fd. The restart dropped that fd and did not start the public socket. `ss` no longer showed `78.46.98.73:8443`. `172.18.0.1:8444` remained. The immediate curls were HTTP 401 and HTTP 200, so this was not rolled back.

`docs/runbooks/2026-10-19-door-public-cert.md` now describes that order. This file is the record of the run.
